# TraceGraph

Рабочее место для расследования ИБ-инцидентов: на входе — `alert` и набор данных по кейсу
(сетевые логи `Zeek`, при необходимости `PCAP`), на выходе — сохранённый ход расследования аналитика:
гипотезы, проверенные факты и обоснованные выводы.

Смысл проекта — не "ещё один просмотрщик логов", а инструмент, который фиксирует цепочку **alert -> гипотеза -> проверка -> доказательство -> статус -> вывод**, чтобы расследование можно было воспроизвести и показать другому человеку.

## Сценарий работы

1. Открыть кейс (например, `case_001`).
2. Увидеть исходный alert и связанные с ним события.
3. Сформулировать гипотезу («хост обращался к подозрительному домену»).
4. Прикрепить к гипотезе конкретные события как доказательства.
5. Отметить гипотезу: подтверждена / опровергнута / неясна.
6. Сохранить состояние расследования.

## Структура репозитория

```
tracegraph/
├── cli/                 # CLI на Go: загрузка кейсов в backend
│   ├── cmd/             # команды: upload, status, get
│   ├── internal/        # bundle (упаковка кейса) и client (HTTP-клиент)
│   ├── tools/mockserver # мок-сервер backend для локальной разработки
│   └── testdata/case_001
└── frontend/            # интерфейс расследования (React + Vite + TypeScript)
    └── src/components/  # AlertCard, EventsTable, HypothesesList, EvidenceList, HypothesisForm
```

Backend (API для кейсов и гипотез) — в разработке, добавляется в этот же репозиторий.

## Быстрый старт

### CLI (папка `cli/`)

Требуется [Go](https://go.dev/) 1.22+.

```bash
cd cli
go build -o tracegraph-cli .        # Windows: go build -o tracegraph-cli.exe .

# поднять мок-сервер backend (в отдельном терминале)
go run ./tools/mockserver

# загрузить тестовый кейс
./tracegraph-cli upload ./testdata/case_001

# статус и полное состояние кейса
./tracegraph-cli status <case_id>
./tracegraph-cli get <case_id>
```

Адрес backend определяется так: флаг `--backend` -> переменная окружения `TRACEGRAPH_BACKEND` -> по умолчанию `http://localhost:8000`. Флаг ставится **перед** аргументом:

```bash
./tracegraph-cli upload --backend http://localhost:9000 ./testdata/case_001
```

Папка кейса должна содержать: `alert.json`, `dns.log`, `conn.log`, `ground_truth.json`.

### Frontend (папка `frontend/`)

Требуется Node.js 20+.

```bash
cd frontend
npm install
npm run dev        # дев-сервер Vite
```

Другие команды: `npm run build` (сборка), `npm run preview` (предпросмотр сборки), `npm run lint` (oxlint).

> Сейчас интерфейс работает на локальных тестовых данных (`src/mockCase.ts`); подключение к API — следующий шаг.

### Тесты

```bash
cd cli
go test ./...
```

## Тестовый кейс case_001

Учебный инцидент: хост `10.0.0.5` генерирует аномальные DNS-запросы и попытки соединений с подозрительными адресами (возможно DNS-туннелирование или активность C2). Файлы кейса — `cli/testdata/case_001/`:

- `alert.json` — исходный сигнал, с которого начинается расследование;
- `dns.log`, `conn.log` — нормализованные логи Zeek;
- `ground_truth.json` — что произошло на самом деле (для проверки правильности выводов).

Кейс используется как regression-эталон: после любых изменений он должен загружаться и обрабатываться без ошибок.

## Как мы разрабатываем

- Код попадает в `main` только через Pull Request из отдельной ветки; напрямую в `main` не пишем.
- Перед PR: `go test ./...` в `cli/` и `npm run lint` в `frontend/` должны проходить.
- Форматы данных (Case, Alert, Event, Evidence, Hypothesis) фиксируются в одном общем контракте — фронтенд, CLI и парсеры ориентируются на него.
